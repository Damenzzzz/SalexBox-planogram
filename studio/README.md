# Planogram Studio · табак

Веб-приложение для планограмм табачных шкафов, связанное с Salesbox Shelf IR. В нём собирают шкаф в миллиметрах, раскладывают пачки по рядам толкателей, согласуют планограмму и публикуют её в IR на нужные точки. Дальше фото агента с этих точек сверяются с ней автоматически. Человек подтверждает слоты, и из этих подтверждений считается реальная точность IR.

План и решения Р1–Р7: https://claude.ai/artifact/EtsCxjoMZko3wXUrGwt6VD

## Запуск

```bash
npm install
npm run dev          # http://localhost:5173
npm run build        # статическая сборка в dist/
```

Серверная часть живёт в IR-сервисе `~/SalesBox(work)`, ветка `islambek/planogram-studio`: хранение, публикация, назначение на точки, фото эталонов.

```bash
cd "~/SalesBox(work)" && git switch islambek/planogram-studio
uv run salesbox-api  # 127.0.0.1:8000; Studio ходит туда через прокси Vite (/v1, /readyz)
```

Подключение настраивается кнопкой в правом верхнем углу: адрес, ключ API и «Хранить на сервере». Другой адрес для прокси разработки задаётся так: `SALESBOX_API=http://host:port npm run dev`.

В проде Studio отдаёт сам сервис: `npm run build`, затем `SALESBOX_API_STUDIO_DIR=<путь>/studio/dist uv run salesbox-api`. Studio открывается на `/studio/`, origin и ключ у неё те же, поле адреса остаётся пустым.

## Что внутри

| Раздел | Что делает |
|---|---|
| Шкафы | Библиотека шаблонов с кодом вида `С1-96-170`: номер, ширина и высота в см, код можно задать свой. Конструктор: полки тянутся мышкой или двигаются стрелками, синие ручки меняют ширину и высоту шкафа. Ещё в конструкторе: цоколь, лайтбокс, дверцы, материал, ширина рядов толкателя, вместимость по форматам пачек |
| Планограммы | Шкаф из библиотеки плюс раскладка. Есть перетаскивание, фейсинги, три режима холста («Текстура», «Схема», «IR-вид»), правила (must-have, доли по контракту, близнецы для IR) и проверки. **Авто**: «Разложить по правилам» и «Подогнать под другой шкаф». **Выгрузить**: YAML для IR, Excel, PNG, печать или PDF, прайс-лист, JSON. **Черновик по фото**: IR находит ряды и пачки на фото точки или на картинке планограммы |
| Согласование и версии | Черновик → на согласовании → утверждена → опубликована, с комментарием на каждом шаге. Правка утверждённой или опубликованной планограммы начинает новую версию, а прежняя остаётся снимком. Во вкладке «Версии» видна история, сравнение «было / стало» и восстановление |
| Публикация | Версия уходит в IR неизменной (`PUT /v1/planograms/plg-…-vN`) и назначается кластерам и отдельным точкам (`PUT /v1/assignments`). После этого фото с этих `outlet_id` IR сверяет с ней сам, поле `planogram` в запросе не нужно |
| Точки | Кластеры точек: сеть, город, формат. Таблица «что назначено каким точкам» берётся с сервера |
| Каталог SKU | 265 меток галереи `recognition_ref` с числом эталонов. Правятся производитель, сегмент, формат, размеры, цена и EAN; можно добавить свои SKU |
| Сверка IR | «Фото → IR» отправляет фото вместе с планограммой. Статусы видны и на фото, и на шкафу. Слоты подтверждаются клавишами: Enter — IR прав, X — ошибся, плюс можно указать, какая пачка стоит на самом деле. В памяти IR: точность, ошибка compliance по набору моделей, SKU, которые IR узнаёт хуже всего, пары-путаницы, счётчик до 50 проверенных фото. Отсюда же «Новая версия по фото», Excel со сверками и **«Эталоны в галерею»**: ZIP с кропами подтверждённых слотов в папках `бренд/модель` для `salesbox-gallery` |

### Хранение на сервере

При включённом «Хранить на сервере» шкафы, планограммы, версии, кластеры, правки каталога и сверки уходят в `studio.sqlite` IR-сервиса и приходят на другие компьютеры. Синхронизация идёт через 2 с после правки и раз в 15 с.

- Браузер остаётся рабочей копией: без сети всё работает, изменения уйдут при связи.
- Если тот же документ правили в двух местах, берётся серверная версия, а своя планограмма сохраняется копией «(ваша правка)».
- Примеры, которые Studio создаёт в новом браузере, уходят на сервер только если он пустой.

Без сервера всё хранится в `localStorage`, а для обмена есть «Выгрузить всё» и «Импорт». Оригиналы фото не сохраняются нигде: кропы для галереи режутся из фото текущей сессии.

### Фото эталонов вместо нарисованных пачек

Если в сервисе задана `SALESBOX_API_GALLERY_IMAGES_DIR` (папка `<бренд>/<модель>/*.jpg`, та же, из которой `salesbox-gallery` строит векторы), пачки на холсте рисуются настоящими фото, как их видит IR. Для остальных SKU по-прежнему работает генератор.

### Прайс-лист

Лист для закрытой выкладки (РК, ст. 110 Кодекса «О здоровье народа»): только текст, чёрный по белому, по алфавиту, с ценой, без изображений. Формат A4 укладывается в предел 40×30 см на одно место продажи. SKU без цены в лист не попадают, Studio их перечисляет.

Импорт принимает JSON v2 (родной формат), JSON v1 прототипа `planogram-studio-handoff` (см переводятся в мм) и YAML из `configs/planograms`.

## Устройство

```
src/domain/     модель и логика без React: типы, форматы, каталог, геометрия, проверки,
                YAML для IR, JSON v2/v1, сверка (compare), версии и сравнение (versions),
                авто-раскладка и подгонка (layout), черновик по фото (draft), выгрузки (exports, xlsx),
                клиент сервиса (api) и синхронизация (sync)
src/render/     Canvas 2D: генератор текстур пачек, фото эталонов (gallery), сцена шкафа
src/ui/         экраны: Planograms, Fixtures, Constructor, Editor, Workflow (согласование, версии,
                публикация, авто), Catalog, Compare, Outlets, Print (печать и прайс-лист), Server
src/store.ts    zustand + localStorage, синхронизация с сервером, хеш-маршруты
src/data/gallery.json   снимок меток галереи и числа эталонов
```

Обновить снимок галереи:

```bash
cd "~/SalesBox(work)" && .venv/bin/python -c "import numpy as np,collections,json;d=np.load('outputs/recognition/gallery_shelf.npz');c=collections.Counter(map(str,d['labels']));print(json.dumps({'source':str(d['source']),'embedder':str(d['embedder']),'snapshot':'<дата>','labels':[{'label':k,'refs':v} for k,v in sorted(c.items())]},ensure_ascii=False))" > ~/planogram/studio/src/data/gallery.json
```

## Чего пока нет

- Вход по пользователям и роли («кто согласует»). Сейчас доступ к серверу даёт ключ API, а в журнале согласования нет автора.
- Хранилище сервиса — SQLite, рядом с `api.sqlite`. Postgres подключается в том же модуле, `service/.../api/studio.py`.
- Размеры пачек приблизительные: нужен замер 20 самых частых SKU.
- Импорт PDF-планограмм. Картинка планограммы проходит через «Черновик по фото».
